# Experiment configurations

`evaluation/*_libero10_patch3_probe.json` are portable, checksummed templates
for the two completed 500-rollout conditions. Paths are relative to an explicit
artifact root. `das prepare-evaluation` binds checkpoint identities, verifies
weights, feature/Probe compatibility, pinned external sources, and records the
active runtime in a new schema-1 configuration. It does not modify weights,
thresholds, intervention, seeds, or rollout parameters. Keep the generated
configuration unchanged across workers and resume. Local absolute paths are
only introduced in that generated, untracked configuration.

| Template | Detector → intervention | Feature | Strength | Replan | Camera |
|---|---|---:|---:|---:|---|
| pi05_libero10_patch3_probe | PG0 → PG5 | 902 | 0.3 | 5 | Agent only, masked wrists |
| smolvla_libero10_patch3_probe | VLM0 → VLM9 | 123 | 0.2 | 1 | Agent and wrist |

Both use Probe gating, seed/overlay seed 1, three ten-step bursts, ten
warmup and denoising steps, maximum 520 control steps, ten tasks × fifty
initial states. The serialized `protocol` records fixed patch geometry,
clock, queue, noise, and success semantics. These are validated settings.
**Paper table numbers are unconfirmed**: no paper source or table-to-run
mapping was provided. `paper.table` is deliberately null. Condition names
and original configuration checksums provide the current traceable mapping.
No unverified conditions are claimed to correspond to paper tables.

Selection and Probe examples are generated by `examples/make_sample_data.py`.
These tiny synthetic inputs illustrate CLI usage; they are not paper training data or scores.
The selection config lists SAE and NPZ episodes (`activations [steps, hidden]`,
`patch_signal [steps]`, `policy_forward_signal [steps]`) with expert, layer,
episode_id and task_id. It delegates masking, encoding, Pearson computation,
aggregation and ranking to the existing APIs. Unknown options are rejected.

Probe config `data.layout` supports `dense`, `paired`, `episodes`, or `arrays`.
The first three call the existing collection readers with `root` and their
API arguments: dense `representation`, paired `layer`, episodes `family`,
`layer`, optional `fold`. `arrays` explicitly supplies `representation`,
`split_unit`, `train`, `dev`, optional `test`. Each NPZ contains `clean`,
`attack` float32 matrices and optionally `clean_task_ids`, `attack_task_ids`,
`clean_episode_ids`, `attack_episode_ids`. IDs must satisfy the library split
constraints. `training` maps to `ProbeTrainingConfig`; no implicit splitting,
resampling, conversion or optimizer substitution occurs. All data paths are
relative to the configuration file. Outputs require new paths.

Full paper retraining requires the original activation collections, whose
release license, download location, and complete inventory remain pending.
Evaluation uses saved Probe/selection and does not require those collections.

Versioned Probes keep their recorded residual representation during preparation.
An unspecified checkpoint identity (`null`) remains unspecified; the explicitly
checksummed evaluation checkpoint still binds the intervention. A recorded
checkpoint path that conflicts with the local checkpoint is rejected. Relocating
such an artifact requires an explicit Python-API migration after establishing
checkpoint identity; the CLI does not silently rewrite Probe metadata. Legacy
NPZ files continue to be bound to the template's explicit representation.
